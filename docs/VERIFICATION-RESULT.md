## 〇、真机验证

### 三个测量污染源（这一节的教训比结论更重要）

我一开始得出了一堆错误结论，根因是三个环境因素在污染实验：

| 污染源 | 造成的假象 | 怎么发现的 |
|---|---|---|
| `ELECTRON_RUN_AS_NODE=1`（由执行环境注入） | 我启动的"Electron"其实是**纯 Node**，报 `bad option: --no-sandbox`，退出码 9 | 报错文本是 Node 的措辞，不是 Chromium 的 |
| 工作区文件沙箱 | 应用在工作区内启动时 Chromium 子进程初始化失败（`0xC0000005` / `0x80000003`） | 把同一份打包产物复制到 `%TEMP%` 后**完全正常** |
| 我习惯性加 `--no-sandbox` | 托盘 `getBounds()` 恒为 0、`Notification.isSupported()` 返回 false | 去掉该参数后两者立刻恢复正常 |

**结论**：真实用户（双击 exe，普通路径，无特殊环境变量）不受任何一条影响。

### 真实故障只有一个：Electron 45 与本机不兼容

最小应用（只有 `app.whenReady()` + 一个窗口）在 Electron 45 下崩在 `main.js` 加载之前，
换成 **38.8.6** 后 whenReady → 窗口 → 页面加载全部正常。项目已降到 38。

对照：VS Code（Electron 3x）与 Chrome 都能正常运行，所以不是机器整体不行。

### 真机跑出来的两个真问题（已修）

| 问题 | 现象 | 修复 |
|---|---|---|
| 默认菜单栏还在 | 窗口顶部有 File/Edit/View/Window/Help | `Menu.setApplicationMenu(null)` |
| 窗口超出屏幕 | 本机 175% 缩放，逻辑分辨率仅 ~1045×653，而默认开 1180 宽 | 按 `workAreaSize` 收敛尺寸，`minWidth` 降到 720 |

## 六、API Key 来源（2026-10-31 新增）

### 结论：可以直接用 DSH 的 Key，而且一直在用

```
未设置环境变量 DEEPSEEK_API_KEY
~/.dsh/.credentials.yaml  →  refs.DEEPSEEK_API_KEY: sk-***（35 字符）
issuer: https://platform.deepseek.com   →  官方平台 Key
```

`resolveApiKey()` 早就在读这个文件（`compose-once` 打印过"已找到（长度 35）"）。
所以本机开发态、命令行脚本、以及**打包后的应用**都能正常调用模型。

### 为什么还要做加密存储

依赖 `~/.dsh/` 有两个问题：

1. 那是 DSH 的内部格式（records / grants / refs 结构），随时可能变
2. 用户重装或清理 DSH，Meerkat 就退回聚合模式，且没有任何提示

所以把它升级成正式能力：

| 来源 | 优先级 | 说明 |
|---|---|---|
| Meerkat 本地存储 | 1 | `userData/secret.bin`，用 `safeStorage` 加密（Windows 走 DPAPI） |
| 环境变量 `DEEPSEEK_API_KEY` | 2 | 开发态与脚本用 |
| `~/.dsh/.credentials.yaml` | 3 | 本机现成可用，设置页提供**一键导入** |

设置页的"模型与密钥"面板显示：来源、打码后的 key、以及是否存在可导入的 DSH 凭据。
导入后落到本地加密存储，之后不再依赖 DSH 的文件。

### 测试

`tests/credentials.test.ts` 11 个测试，重点是不泄露：

- `maskKey` 保留前 7 位与后 2 位，中间恒为 `***`
- `parseDshCredentials` **不会**把 `records` 里的 `token` / `secret` 误当成 API Key
- 只匹配 `sk-` 前缀，不会捞出别的凭据
- `looksLikeDeepSeekKey` 拒绝 `ghp_` 之类的错误输入

### 分发时的注意

这把 Key 是账号凭据，**不能打进安装包**。别人装完需要用自己的 Key——
面板里的输入框就是为此准备的（他们机器上没有 `~/.dsh`，只能手填）。

另：每次生成约消耗 1 万输入 + 1.4 万输出 token。每天跑一次量很小，但会计入你的账号配额。
