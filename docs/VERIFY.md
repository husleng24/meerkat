# 真机验收清单

> 这份清单只做一件事：把"我这边无法验证的部分"用最少的操作验证掉。
>
> 背景：开发机上 Electron 的 Chromium 无法初始化（`--verify` 也会崩在 crashpad），
> 因此**所有涉及窗口、托盘、通知的行为一次都没跑过**。数据层与打包布局已经验证过。

每个步骤都写了「预期」和「失败的样子」，失败时把对应输出贴回来即可。

---

## 第 1 步 · 自检（1 分钟，最重要）

在项目目录执行：

```powershell
pnpm verify:app
```

它不创建窗口、不进 Chromium 渲染，只检查数据层与资源：userData 可写、数据库迁移、
35 个源入库、中文 FTS 检索、标志位读写、排程读取、托盘点阵图标能否解码。

**预期**：13 行全部 `[ OK ]`，最后一行 `全部通过`，并在
`文档/Meerkat/自检报告.txt` 写一份报告。

**失败的样子**：

| 失败项 | 含义 | 我要看到什么 |
|---|---|---|
| `userData 目录可写` | 权限或杀软拦截 | 完整错误文本 |
| `源配置 sources.json` | 打包漏了 extraResources | 它打印的路径 |
| `数据库打开与迁移` | 原生模块没解包 / ABI 不匹配 | 完整错误文本 |
| `条目表可写（中文 + FTS）` | FTS5 或 trigram 不可用 | 完整错误文本 |
| `托盘图标可解码` | 图标缺失或损坏 | 它打印的路径 |

如果这一步就全绿，说明**数据层没问题是确定的**，后面几步只验证界面层。

---

## 第 2 步 · 开发态启动窗口（2 分钟）

```powershell
pnpm dev
```

**预期**：出现 1180×820 的窗口，左侧是 Meerkat 侧栏，主体是简报页。

要检查的四点（每点都写"失败的样子"，便于你判断是不是 bug）：

1. **首次启动应该有引导页**（选领域 → 确认源 → 接模型）。
   - 如果没有：可能是数据库中已有数据（属正常），点侧栏「设置」看排程。
2. **简报页有没有内容**。
   - 首次运行还没采集过 → 会显示「还没有简报」，这是**正常的**。先做第 3 步。
3. **侧栏「源」页有没有 33–35 个源，且状态列有绿点在跑**。
   - 若显示「预览模式」字样 → 说明 preload 没加载成功，这是**真 bug**，请告诉我。
4. **按 `j` / `k` 能不能上下移动选中框，按 `s` 能不能收藏**。
   - 收藏后侧栏「已收藏」计数应该 +1；**关掉窗口再开，应该还在**（这是 P2-4 的验收点）。

---

## 第 3 步 · 手动采集一次（2 分钟）

在「设置」页点 **立即采集**。

**预期**：按钮变成「运行中…」，1–2 分钟后提示
`完成：34/35 源成功，入库 80 条`，随后「今日」页出现简报。

**失败的样子**：

- 提示「未接模型（降级）」→ API Key 没读到。开发态需要环境变量：
  ```powershell
  $env:DEEPSEEK_API_KEY = "sk-..."
  pnpm dev
  ```
  或者确认 `~/.dsh/.credentials.yaml` 里有 `DEEPSEEK_API_KEY`。
- 一直停在「运行中…」→ 可能某个源卡住（默认 25s 超时 × 3 次重试）。
  等 3 分钟仍未结束就是 bug，把「设置」页截图给我。
- 报 `HTTP 429` 之类但整体成功 → 正常，Reddit 长期限流是已知情况。

---

## 第 4 步 · 托盘与关窗行为（3 分钟，最容易出问题）

**这是最需要验证的一步**，因为它是"无人值守"的前提，而我完全没跑过。

1. 看**任务栏右下角托盘区**，是否有一个小狐獴图标（可能在「^」展开里）。
2. 点窗口右上角 **×** 关闭。
   - **预期**：窗口消失，但**应用没退出**（托盘图标还在）。
   - 失败的样子：进程没了 / 托盘图标也没了 → `close` 拦截没生效。
3. **右键托盘图标**，应该看到菜单：`排程：每天 08:30`、`下次：…`、`打开简报`、
   `立即采集`、`导出今日简报`、`退出`。
4. 点 **打开简报** → 窗口应该回来。
5. 点 **立即采集** → 应该在后台跑完并弹一条系统通知。
6. 点 **退出** → 进程真正结束。

> 注意：Windows 的「专注助手 / 勿扰模式」会吞掉通知。如果第 5 步没弹通知，
> 先确认系统通知设置里 Meerkat 是允许的，再判断是不是 bug。

---

## 第 5 步 · 定时与补跑（5 分钟）

不用等到明天早上，改一下时间即可：

1. 「设置」页把时间改成**当前时间 + 2 分钟**，保持开关打开。
2. 关掉窗口（收进托盘），不要再动它。
3. 等到点后观察：
   - **预期**：托盘图标菜单里的「下次」更新为明天，并弹通知；
     打开窗口能看到新简报。

**另一个更快的验证方式**：直接把时间设成一个「2 小时前的整点」，然后重启应用。
按设计它应该**在启动时补跑一次**（补跑窗口 6 小时）——`decideDue` 的 `catch-up` 分支。

**失败的样子**：到点没动静。此时把 `%APPDATA%\Meerkat\logs\main.log` 最后 30 行贴给我。

---

## 第 6 步 · 打包版（3 分钟）

```powershell
pnpm dist
.\release\Meerkat-0.0.1-便携版.exe
```

便携版是单文件自解压，首次启动会慢几秒（正常）。

**要检查的**：跟开发态一样能开窗口、能看简报、托盘图标在。
重点确认**它读得到自己的资源**——打包版的 `sources.json` 和提示词在
`resources/resources/` 下，路径解析走的是 `process.resourcesPath` 分支。

如果打包版打不开窗口但 `pnpm dev` 正常 → 大概率是资源路径或 asar 的问题，
请把 `%APPDATA%\Meerkat\logs\main.log` 给我。

---

## 第 7 步 · 诊断包（1 分钟，顺手验证）

「设置」页 → **导出诊断包**。

**预期**：提示 `诊断包已导出到 …\文档\Meerkat\Meerkat-诊断-….json`。

**顺便做一次泄露检查**（重要）：用记事本打开那个 json，
搜索 `sk-`，**应该搜不到任何真实密钥**。如果搜到了，立刻告诉我——那是严重问题。

| 现象 | 原因 |
