# 领域（主题）导航：调研与设计方案

> 状态：调研 + 方案，未实现。2026-11-01。
> 问题：现在「领域」信息不清楚——侧栏只有一个下拉框，看不出有哪些领域、各自有多少内容，
> 也不知道当前页面属于哪个领域。是否应该把领域做成侧栏分类？有没有更好的做法？

---

## 一、现状（实测截图）

多领域时（截图里 3 个），侧栏顶部是：

```
主题
[ 具身智能        ▾ ]
今日 / 搜索 / 时间线 / 源 / 设置
```

四个具体问题：

| # | 问题 | 后果 |
|---|---|---|
| 1 | 领域是一个**原生下拉框** | 看起来像表单控件而不是导航；要看有哪些领域得先点开 |
| 2 | 看不到**每个领域有多少内容** | 无法判断"今天哪个领域有新东西"，只能逐个点开 |
| 3 | 内容区标题只有「今日简报」 | 不清楚「时间线」「源」是不是也切了领域 |
| 4 | **只有一个领域时**退化成一行静态文字 | 没有任何"切换 / 新建"的入口，功能等于隐藏 |

> 另：界面文案在「主题」（侧栏）与「领域」（引导页）之间摇摆，本身也是"不清楚"的一部分。

## 二、调研：别人怎么放"作用域"

### 2.1 Multica —— 作用域用切换器，和导航分层

侧栏顶部是**工作区名**，点开切换/创建工作区；下面才是聊天、任务、智能体等功能项。
关键点：**作用域（workspace）与功能项（导航）是两层**，作用域用"当前值 + 下拉"表达。

> 出处：[完整教程](https://multica.ai/docs/zh/tutorial)（"点击侧边栏顶部的工作区名称，选择创建工作区"）

### 2.2 Readwise Reader —— 侧栏是可配置的"视图"

侧栏里 Home / Library / Feed / Search 固定，其余视图**可 pin / 取消 pin / 拖拽排序**，
另有独立的「Manage views」页面统一管理。

> 出处：[Navigation](https://docs.readwise.io/reader/docs/faqs/navigation)

启示：侧栏的东西多了以后，"管理"必须有一个落点，不能全靠就地操作。

### 2.3 常见模式归纳

| 模式 | 代表 | 适合 |
|---|---|---|
| 顶部切换器（dropdown） | Slack / Notion / Multica | 作用域多、每个作用域内容重、切换不频繁 |
| 侧栏分组列表 | Readwise 的 pinned views、Feedly 的 boards | 作用域少（2–6 个）、需要一眼看到各自体量 |
| 内容区 tab | 大多数后台 | 同一份数据的不同切片，切换不改变导航 |
| 合并流（分组展示） | 邮件客户端的"全部收件箱" | 不想切换，只想一次看完 |

## 三、三个候选方案

![三种方案对比](assets/topic-nav-mockup.png)

### A. 侧栏「领域」分组列表（推荐）

领域作为侧栏上半部分的一组可点项，每行：名称 + 今日条数；当前项高亮；底部「＋ 新建领域」。

- 可发现性：高（一眼看到全部领域与各自条数）
- 切换成本：一次点击；支持 `⌘1–9`
- 扩展性：≤6 个舒服，更多需要滚动 + 「管理领域」

### B. 顶部切换器（现方案的下拉版，只修样式）

- 切换两次点击；信息被折叠；但作用域与导航分层清晰，领域多了也不乱
- 与现状差别最小，解决不了"看不到各领域体量"

### C. 内容区顶部 tab

- 领域放在「今日简报」标题上方作 tab；侧栏保持全局
- 问题：与页面标题争夺层级；切换时正文整体重排，阅读位置丢失；「时间线/源」不属于 tab 的管辖范围，语义割裂

### 对比

| 维度 | A 侧栏列表 | B 切换器 | C 内容 tab |
|---|---|---|---|
| 看到全部领域 | ✅ 常驻 | ❌ 需点开 | ✅ |
| 看到每个领域的内容量 | ✅ 每行带数字 | ⚠️ 只能放下拉项里 | ⚠️ 依赖 tab 宽度 |
| 切换步数 | 1 | 2 | 1 |
| 与「今日/时间线/源」的关系 | 作用域，清晰 | 作用域，清晰 | 只有今日页受控，语义割裂 |
| 领域 > 6 时 | 需要滚动/管理页 | ✅ 天然可扩展 | 横向溢出 |
| 实现成本 | 中（0.5–1 天） | 低（0.5 天） | 中高 |

**结论：选 A。** 这个产品的领域数量是个位数（AI 综合 / 芯片与算力 / 具身智能 / 开发者工具），
而"今天哪个领域有新东西"正是用户每天第一个要回答的问题——把它折叠进下拉框是浪费。

## 四、方案 A 的细节

### 4.1 布局

```
领域                        ← 小标题（10px，间距 0.1em）
● AI 综合              23   ← 当前项：accent-soft 底 + accent 字
  芯片与算力            12
  具身智能               9
  ＋ 新建领域              ← 就地输入，复用 topics:create
────────────────────────
今日
搜索
时间线
源                    15
设置
```

- 与导航之间一条分隔线即可，不再加"视图"小标题（侧栏已经很窄，多一级标题反而吵）
- 每行的数字＝该领域**最新一期简报的条目数**；没有简报显示 `—`，不用 0（0 会被误读成"今天没新闻"）
- 当前项左侧不用竖条（与现有设计语言一致：浅底 + 主色文字）
- 「源」仍显示需关注数（红色），与领域数字区分：一个是内容量（灰），一个是警报（红）

### 4.2 作用域说明

- 「今日」「时间线」跟随领域；「搜索」保持全库（搜索是找东西，不该被作用域限制）
- 内容区标题上方加一个领域 chip：

```
[AI 综合]
今日简报
2026年11月1日 周日 · 覆盖最近 48 小时 · 23 条
```

- 切换领域时**停留当前页**（在时间线就留在时间线），只换数据
- 空领域：内容区显示「这个领域还没有简报」+「立即采集」按钮（复用 header 的更新）

### 4.3 交互与快捷键

| 操作 | 行为 |
|---|---|
| 点击领域行 | 切换并记住（localStorage，已有） |
| `⌘1`–`⌘9` | 切到第 N 个领域 |
| 「＋ 新建领域」 | 就地出现输入框，回车创建并切过去；Esc 取消 |
| 领域行右键（可选） | 重命名 / 设置（跳到设置页对应位置） |

### 4.4 数据

`topics:list` 现在返回 `sourceCount` / `hasBrief`，增加两项：

```ts
todayCount: number      // 最新一期简报的条目数；无简报为 0，界面显示「—」
unreadCount: number     // 可选：该领域未读条目数（P1）
```

实现：对每个领域取 `briefs.latest(topicId)`，解析 markdown 计条目，或直接用 `items` 表统计当天；
前者与「今日条目」口径一致，选前者。

### 4.5 命名：统一叫「领域」

现在代码里叫 topic，侧栏写「主题」，引导页写「领域」。建议**界面统一为「领域」**：
引导页已经用它教育过用户，且「芯片与算力」「具身智能」这类词本来就是领域而不是主题。
代码里的 `topic` 不改（改名成本大于收益）。

### 4.6 边界

- 领域 = 1 时：**照样显示列表**（一行 + 新建），不要退化成一个标题——可发现性比"省一行空间"重要
- 领域 > 6：列表加 `max-height` 与滚动；分组标题右侧出现「管理」，跳到设置页主题区块
- 领域名过长：截断 + tooltip（216px 宽，中文 10 字以内安全）

## 五、实施拆分（约半天到一天）

1. **数据**：`topics:list` 增加 `todayCount`（主进程，`briefs.latest` + 简单条目计数）；补 1 个测试
2. **侧栏**：把 `<select>` 换成领域列表组件（含新建入口、快捷键、空/单领域状态）
3. **内容区**：报头加领域 chip；空领域状态
4. **文案**：侧栏「主题」→「领域」；设置页区块同步
5. **验收**：见下

## 六、验收标准

- 三个领域时，侧栏一屏内看到全部领域与各自今日条数
- 切换领域一次点击完成；`⌘1–9` 生效；刷新后停留在原领域
- 只有一个领域时，仍能看到「＋ 新建领域」
- 领域没有简报时显示「—」与空状态，不显示 0 条
- 内容区标题能看出当前领域；时间线随领域切换，搜索不受影响
- 组件测试：切换回调、数字显示（`—` vs `n`）、新建流程的 Esc/回车行为
