# Meerkat Roadmap

> 从「AI 日报」走向「个人决策终端」。
>
> 判断标准：每个功能是否让用户在**更短时间内做出更可信的判断**；不以信息量、源数量或功能数量为目标。

## 核心公式

```text
价值 = 相关性 × 新颖性 × 可信度 × 可行动性 / 获取时间
```

Meerkat 已经解决相关性（主题/源/编辑重点）、新颖性（48h + 跨天去重 + no-change）和可信度（来源依据/链接校验/降级可见）。下一阶段补的是**可行动性**与**获取时间**。

## P0：决策层

### 1. 决策笔记（本迭代）

在任意一条简报内容下写一句自己的判断，本地保存：

- 我认为会影响什么；
- 我准备做什么；
- 什么信号出现时说明我判断错了。

为什么：

- 当前产品停在「信息」；没有决策记录，周回顾没有素材，产品也无法证明自己有用。
- 这是和 RSS / newsletter / 通用摘要最直接的差异。

验收：

- 每条内容可以写/改/删判断；
- 判断按条目 id 持久化；
- 刷新、切主题、重启后仍在；
- 有判断的条目在阅读界面可见。

### 2. 周回顾（本迭代）

按最近 7 天聚合：

- 写了哪些判断；
- 对应哪条内容、来源、日期；
- 本周有多少期简报、多少条内容、多少天是 no-change；
- 没有判断的空白状态。

为什么：

- 日报是「输入」，周回顾是「输出」；
- 没有回顾，用户不会记得自己上周判断过什么；
- 这是留存和付费的理由，不是又一个摘要。

### 3. 交付层（下一迭代）

- 每日摘要邮件 / 飞书 / Slack；
- 移动端可读分享页；
- no-change 也能推送；
- 一键转发某条判断/内容。

为什么：用户的早晨不在 Electron 里；只在桌面端等于只在打开 app 时存在。

## P1：记忆层

### 4. 实体与事件

- 公司页、人物页、事件页；
- 融资、产品、裁员、负面；
- 访谈/视频挂到公司/人物；
- 事件时间线与「上周 vs 本周」。

为什么：总结会商品化，**纵向记忆 + 实体关系**不会。

### 5. 信任与评估

- 事实 / 推断 / 传闻标记；
- 来源多样性与单源主导警告；
- 固定评测集：无依据断言率、链接准确率、重复率；
- no-change 的可审计解释。

为什么：可信度是本地优先之外的第二条护城河。

## P2：团队与商业化

### 6. 可选加密同步

本地优先 + 可选云同步，不强制账号；解决换机、移动端和备份。

### 7. 团队空间

共享主题、评论、权限、审计；按团队/席位收费。

### 8. Source pack 市场

把主题 + 源 + 编辑重点做成可分享的包，由创作者/机构维护；这是分发和网络效应。

## 不做

- 无限信息流；
- 用源数量当卖点；
- 通用聊天机器人；
- 独立视频摘要器；
- 没有留存前的社区/社交。

## 验证指标

| 指标 | 含义 |
|---|---|
| 5 分钟完成率 | 打开到关闭是否在 5 分钟内 |
| 决策笔记率 | 每期产生多少条判断 |
| 周回顾回访 | 第二周是否回来看上周判断 |
| no-change 信任 | 空状态后第二天是否回来 |
| 交付打开率 | 邮件/飞书是否进入工作流 |
| 来源包采用率 | 用户是否导入别人的主题配置 |

先找 10 个真实用户做两周 diary study，再决定是否扩功能。
