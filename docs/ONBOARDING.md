# 首启引导（Onboarding v1）

> 2026-11-22 · P0 已实现；P1 的进度、接模型提示和回看入口也已落地。
> 设计稿：[首屏 1180×820](mockups/onboarding-choose.png) · [四态总览](mockups/onboarding-states.png) · [HTML 源文件](mockups/onboarding.html)

## 0. 已确认的决定

| 决定 | 选择 |
|---|---|
| 范围 | **只做新用户首启**，不是常驻导览页 |
| API Key | **首屏不放**；第一份简报之后再引导 |
| 老用户 | **grandfather**，不打扰 |
| 预置 YouTube 主题 | **暂不停用**，保持现状 |
| 形态 | 单屏 + 运行/完成/失败三个状态 |
| 入口 | 首启自动出现；`#onboarding` 只用于回看和开发 |

## 1. 背景：为什么不是“再加一个页面”

仓库里已经有一个 `Onboarding.tsx`，但它目前是死代码：

- 只有手动改 hash 到 `#onboarding` 才能打开；NavRail、设置页、启动逻辑都没有入口。
- `finish` 只创建主题，不跑采集，也不保存 API Key；第 3 步的 Key 输入框没有 `onChange`。
- 选「AI 综合」时，`initStore` 已经建过 `ai` 主题，`topics:create` 返回「主题已存在」被静默忽略。
- 选「芯片与算力」时，主题建出来了，但当前主题没有切过去。

同时，首启启动顺序里有一个更关键的问题：`Scheduler.start()` 会立即 `tick()`，新库的 `ai` 和 `youtube` 两个主题都没有 `lastRunAt`；在早上 6 小时补跑窗口内，两个都会 due。用户还没看到引导，后台已经开始跑 35 + 17 个源。等用户在引导里点「生成第一份简报」，`run:now` 只会返回「正在运行中」。

所以这次不是加一个新页面，而是：

1. 把现有引导页重做成单屏；
2. 接上首启判定；
3. 首启期间让定时器让路；
4. 让“第一份简报”成为引导的终点。

## 2. 目标与非目标

**目标**

- 新用户 10 秒内知道这个产品是什么、为谁做的。
- 只做一个产品配置决定：先盯哪些方向。
- 一次点击拿到第一份简报；等待过程可解释、可取消、可离开。
- 完成状态可持久化：只出现一次；老用户升级不打扰。
- 失败不挡路：错误可读，可重试，也可跳过。

**非目标**

- 不做轮播、多屏动画、逐元素高亮 tour。
- 不在首屏要 API Key，不做“确认源”步骤。
- 不做首启 checklist（会和引导重复）。
- 不引入账号、遥测、云端状态。
- 这次不改预置 YouTube 主题的启用状态。

## 3. 用户流程

### 3.1 首屏：选方向

整页，不用遮罩弹窗。首启时下面没有内容，弹窗会像报错框。

内容顺序：

1. 品牌锁标：图标 + Meerkat + 「只留真正变了的那几条」
2. 主标题：`每天 5 分钟，知道你在意的领域昨天真正变了什么`
3. 说明：`Meerkat 抓取公开信号源，只保留 48 小时内真正变化的内容，写成一份能读完的中文简报。数据留在本机，不需要账号。`
4. 区块标题：`先盯哪些方向？`
5. 说明：`选一个或多个；每个方向有自己的源和简报，之后随时可改。`
6. 四张方向卡（2×2）：
   - AI 综合：模型 / Agent / 研究 / 产品；`35 个源`
   - 芯片与算力：GPU、代工、数据中心；`推荐约 8 个源`
   - 具身智能：人形、灵巧手、世界模型；`推荐约 8 个源`
   - 开发者工具：IDE、CLI、SDK、Agent 框架；`推荐约 8 个源`
7. 左下「跳过，先进入」；右下主按钮「生成第一份简报」。
8. 按钮下方小字：`第一份大约需要 1–2 分钟；不接模型也能出「仅聚合」版。`

交互规则：

- `AI 综合` 默认选中；用户可取消，但至少要留一个方向才能点主按钮。
- 方向卡用 `aria-pressed`；选中态同时有靛蓝描边、浅底和勾，不只靠颜色。
- 新方向显示「推荐约 8 个源」；已有主题显示真实的 `topic.sourceCount`。
- 首份简报只跑**选中方向里排在最前的一个**（按卡片顺序，不按点击顺序），界面不额外解释；其余方向之后按排程跑。
- 「跳过」始终可用，不做二次确认。

### 3.2 运行

点「生成第一份简报」后：

1. 补齐选中的、尚不存在的主题；已存在的按 id 复用，不覆盖用户改过的设置。
2. 新主题带上各自的 `editorialFocus`，并尽量补上推荐源。
3. 把当前主题切到首个选中方向。
4. 调用 `onboarding:start({ topicId })`。

运行态显示：

- 标题：`正在生成第一份简报`
- 说明：`抓取「AI 综合」的 35 个源，通常 1–2 分钟。可以最小化窗口，采集会在后台继续。`
- 状态卡：`正在抓取公开信号源` + `已用 00:23`
- 说明：`跑完这里会显示结果；也可以先关掉窗口，稍后再回来。`
- 左下「取消」。

**不要做假进度。** 现在没有逐源进度事件，因此只显示已用时间，不显示百分比。若以后加进度条，把它作为视觉规范里的唯一例外，并在 `prefers-reduced-motion` 下关闭。

取消后回到选方向，保留已选方向；不要报成失败。

### 3.3 完成

- 标题：`第一份简报好了`
- 副行：`「AI 综合」· 2026-11-22 · 24 条。之后每天按排程自动跑，也可以在报头点「更新」。`
- 结果卡：`34/35 源成功`、`24 条内容`、`23/24 链接校验`
- 若 `degraded`：一个浅色说明块，`仅聚合` 标签 + `这次没接模型：先列标题、来源和链接。接上模型后，会写成三句话速览。`
- 若失败源 > 0：补一句 `2 个源这次没成功，可在「事实源」页看原因。`
- 若 `noChange`：改成 `今天没有值得改变判断的变化`，不要让用户以为跑失败。
- 主按钮：`去读简报`。

完成页只负责“结果确认 + 去读”，不再插入接模型、设提醒等动作。接模型的提示放到今日页（P1），避免在首份简报前又开一屏。

### 3.4 失败、取消、跳过

| 情况 | 处理 |
|---|---|
| 采集失败 | 显示可读原因；`重试` + `跳过，先进入` |
| 用户取消 | 回到选方向，保留选择；不写失败状态 |
| 用户跳过 | 写完成标记（`skipped: true`），进入今日页 |
| 已有运行在跑 | 提示「已有一轮在跑」；不写完成标记，等它结束或重试 |
| 关窗/最小化 | 采集在主进程继续；下次打开若已有简报，直接进今日页 |

失败页文案：

- 标题：`这次没跑完`
- 说明：`采集过程中出错了。已经抓到的内容不会丢，可以重试；也可以先进入应用，之后在设置里再跑。`
- 错误卡：`网络连接失败` + `检查网络后重试；也可以先跳过，今日页的「立即采集」还能再跑一次。`

## 4. 首启判定

状态存在 SQLite `settings` 表，key 为 `onboarding.state`：

```json
{
  "version": 1,
  "at": 1763790000000,
  "skipped": false,
  "grandfathered": false
}
```

新增 `src/app/onboarding.ts`：

- `ONBOARDING_VERSION = 1`
- `onboardingStatus(store)` → `{ shouldShow, completedVersion }`
- `markOnboardingComplete(store, { skipped })`
- `shouldDeferSchedule(store)`（定时器让路用）

判定顺序：

1. 有标记：
   - `version < ONBOARDING_VERSION` → 显示（用于以后重大改版重新引导，**不要随便 bump**）。
   - 否则 → 不显示。
2. 没有标记：
   - `briefs.count() > 0 || items.count() > 0` → 视为老用户；`initStore` 写入 `grandfathered` 标记，不显示。
   - 否则 → 显示。

为什么不用 `localStorage`：定时器在主进程，只有主进程能读到的状态才能拦住首启采集。`settings` 也是现有种子标记（`topics.membershipSeeded`）的同类存储，不需要 schema 迁移。

其他规则：

- 浏览器预览 / 没有 preload：`shouldShow = false`，保持现有样例行为。
- `onboarding:get` 失败：fail-open，直接进今日页；手动「立即采集」仍可用。
- `#onboarding`：回看模式，只展示，不写标记、不建主题、不跑采集。
- 老用户升级：不弹；回看入口以后放设置 → 关于（P1）。

## 5. 定时器让路

在 `Scheduler.tick()` 开头判断 `shouldDeferSchedule(store)`，为 true 就 return。托盘「立即采集」也做同样处理，并把托盘提示改成「先完成开始使用」。

原因：新库的 `ai` 和 `youtube` 都没有 `lastRunAt`，早上启动会在引导出现前自动跑两轮。这不是“首启体验”能接受的。

边界：

- 不拦 IPC `run:now`。用户显式点「立即采集」仍应能跑，这是引导失败时的恢复路径。
- 引导完成后，下一分钟 tick 自动恢复；如果用户点了 CTA，`onboarding:start` 已经拿到运行锁，不会重复。
- 预置 YouTube 主题暂不停用（已确认）。所以首份简报之后，它可能按排程自己跑一轮；用户可在设置里停用。这个行为先接受，后续再单独定。

## 6. 主题与源

- 方向 id 固定为 `ai` / `chip` / `robot` / `dev`，与现有旧引导保持一致。
- 已存在同 id 主题 → 直接复用；**不要再对 `ai` 调 `topics:create`**。
- 新主题通过 `topics:create` 创建，传 `domainId`（默认当前领域）和 `editorialFocus`。
- 新主题不传 `sourceIds`，走 `topics:create` 的推荐源逻辑（默认 8 个，见 `src/app/source-recommend.ts` 的 `NEW_TOPIC_SOURCE_LIMIT`）。
- 若选中的已有主题 `sourceCount === 0`，先补推荐源；补不上就在卡片上禁用该方向，不要让用户跑出一个空简报。
- 不做“确认源”步骤；源在设置页可增减。

方向描述与 `editorialFocus` 建议：

| id | 名称 | 描述 | editorialFocus |
|---|---|---|---|
| `ai` | AI 综合 | 模型 / Agent / 研究 / 产品 | 保持默认，不覆盖已有值 |
| `chip` | 芯片与算力 | GPU、代工、数据中心 | 只保留半导体、GPU、代工、数据中心与算力供应链的实质变化；忽略泛 AI 应用与融资新闻 |
| `robot` | 具身智能 | 人形、灵巧手、世界模型 | 只保留人形机器人、灵巧手、世界模型、具身数据与量产进展；忽略纯软件 Agent 与通用模型发布 |
| `dev` | 开发者工具 | IDE、CLI、SDK、Agent 框架 | 只保留 IDE、CLI、SDK、代码托管、Agent 框架与开发者工作流的实质变化；忽略消费级 AI 产品新闻 |

## 7. API 设计

新增三个 IPC：

```ts
onboarding:get
  → { shouldShow: boolean; version: number; completedVersion: number; grandfathered: boolean }

onboarding:start({ topicId })
  → 与 run:now 相同的运行结果
    （ok / nKept / nOk / nSources / degraded / noChange / linkGood / linkTotal / error）
  在拿到运行锁之后写完成标记，再跑采集

onboarding:complete({ skipped: boolean })
  → { ok: boolean; error?: string }

run:status
  → { running: false } | { running: true; kind: 'collect'|'compose'|'scheduled'; topicId?: string; startedAt: number }

run:progress（事件，渲染层订阅）
  → { topicId: string; done: number; total: number; name: string; ok: boolean; n: number }
```

实现要点：

- `onboarding:start` **不要复制一份采集逻辑**。先把现有 `run:now` 的主体抽成一个函数，两个入口共用。
- 先 `beginRun()` 再写完成标记；拿不到运行锁时返回「正在运行中」，不要留下“标记了但没跑”的状态。
- `run:now` 的返回值补 `noChange?: boolean`，完成页要用。
- preload 和 `ipc-types.ts` 补对应类型；`useTopics.create` 的类型补 `domainId` / `editorialFocus` / `sourceIds`。
- IPC handler 继续用 zod 校验；非法入参返回结构化失败。

## 10. 边界情况

- **已有数据的库**：不出现引导；`initStore` 写 grandfather 标记。
- **没有 preload / 浏览器预览**：不出现引导；页面仍可通过 `#onboarding` 查看。
- **`onboarding:get` 失败**：不阻塞启动，进今日页。
- **已有运行在跑**：提示「已有一轮在跑」；不写完成标记。
- **用户取消**：回选方向；保留选择；不写失败。
- **用户跳过**：写 `skipped` 标记；进今日页。
- **采集中关窗/最小化**：主进程继续；下次打开若已有简报，直接进今日页。
- **首份简报降级**：完成页明确写「仅聚合」；今日页后续再提示接模型（P1）。
- **无变化**：完成页写「今天没有值得改变判断的变化」。
- **选多个方向**：只跑第一个；其余之后按排程。
- **预置 YouTube 主题**：暂不停用；首份简报后可能自己跑一轮，接受，后续再定。

## 13. P1（已落地）

- `run:status` / `run:progress`：运行中可查询类型、主题和开始时间；采集阶段逐源推送 12/35。
- 首启运行态和设置页都显示真实逐源进度；今日页空状态如果已有运行，会显示「正在采集」并可取消。
- 首份「仅聚合」简报之后，今日页出现一次「去设置接模型」轻提示，可「以后再说」；历史回看不打扰。
