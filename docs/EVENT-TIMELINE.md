# 条目评论与事件时间线（P0）

> 状态：**P0 已实现**（2026-11-14）。P1 的持续跟踪未做。

## 入口

不设固定的"时间线"按钮：每条新闻的 💬 打开评论串，在评论里 `@agent` 触发整理。

```
条目「黄仁勋辞任英伟达 CEO」
  └─ 💬 评论
      └─ @agent 整理一下这件事的时间线
          └─ AI 回复：时间线卡（阶段 / 来源 / 缺口 / 待确认）
```

## 实现

| 层 | 内容 |
|---|---|
| 数据 | schema v8：`chat_threads` 增加 `scope`（brief/item）与 `item_id`；一条新闻一段评论串 |
| 检索 | `app/event-timeline.ts`：从标题/评论抽实体词（剥掉"辞职/卸任/发布"等事件词），用本地 FTS 找相关条目 |
| 合并 | 同 URL 或标题相似度 ≥0.55 的报道合并，保留多来源 |
| 整理 | `main/item-timeline.ts`：一次模型调用，要求只输出 JSON；失败/未配置模型时退回按日期整理的确定性时间线 |
| 校验 | `sourceItemIds` 必须真实存在，非法引用整段丢弃；单来源自动标 `single-source` |
| UI | `TimelineCard`：阶段、状态（已确认/报道/未证实）、来源链接、时间缺口、待确认问题 |

## 提示词约束

- 只允许使用传入素材，禁止补充外部事实
- 每条必须带来源 id；没有引用的阶段被丢弃
- 官方/一手标 `confirmed`，媒体 `reported`，未证实 `rumor`
- 断档写进 `gaps`，未解问题写进 `openQuestions`

## 已知限制

- **只覆盖本地已采集的数据**（当前 782 条，从 2026-11-01 起），更早的历史无法回填
- **别名依赖规则**：中文"辞职"和英文"resign"不会自动互搜；同一事件换了说法可能漏
- **任何 `@agent` 都会整理时间线**：P0 还没做"只是提问"和"要跟踪"的意图区分
- **不持续跟踪**：没有 stories 表，也不会在下次采集后自动追加
