## 一、阻塞在外部条件

### 🔴 1. NSIS 安装包

**现状**：只发 `zip` 与 `便携版.exe`，没有正式安装包。

**为什么卡住**：electron-builder 生成卸载器时，会用 makensis 打一个 `-DBUILD_UNINSTALLER`
的特殊安装包，然后**执行它**来产出 `Setup.__uninstaller.exe`。这台机器的实时防护
会拦下那个刚生成、未签名的 exe，`exit 2`。

**两条出路**（选一条）：
- 买代码签名证书（OV/EV 均可），配到 `CSC_LINK` / `CSC_KEY_PASSWORD`
- 换一台没有该限制的机器打包

**验收标准**：`pnpm dist` 产出 `Meerkat-x.y.z-Setup.exe`；双击能装、开始菜单有快捷方式、
卸载能干净移除（保留 `%APPDATA%\Meerkat` 数据）。

**它同时挡住下面两件事**（2、3）。

---

### 🔴 2. 通知可靠性

**现状**：真机上 `Notification.isSupported() === true`，代码里也确实调了 `.show()`，
但**没有人肉眼见过 toast 弹出**。

**为什么可能失效**：Windows 的 toast 要求应用有带 AppUserModelID 的**开始菜单快捷方式**。
开发态与解压版没有快捷方式，可能静默失败。

**依赖**：安装包（第 1 项）会在开始菜单创建快捷方式。

**验收标准**：装包后，托盘「立即采集」跑完，系统右下角真的弹出通知；点通知能唤起窗口。

---

### 🔴 3. 自动更新

**现状**：完全没做，`electron-updater` 未引入。

**为什么卡住**：差分下载依赖**已签名的安装包**；而且需要先定更新源。

**需要先做的决定**：
- 更新源用哪个：GitHub Releases / 自建静态目录 / 对象存储
- 通道策略：是否区分 stable / beta

**验收标准**：旧版本能检测到新版本、下载、提示重启、重启后版本号变化。
**没有可用的更新源之前不要写这段代码**——写完也无法验证，会让"能更新"变成假象。

## 三、产品功能缺口

### 🟡 6. 「和昨天比，什么变了」

**为什么重要**：这是原始需求的核心——"我想更快感知 AI 界在发生的变化"。
现在的实现只回答"今天有什么"，不回答"和昨天相比变了什么"。时间线只存了历史，
没有对比视图。

**可能的做法**：
- 简报生成时读昨天那一期，让模型只写"新增/变化"
- 或者界面层做 diff：把当天条目按 id 与昨天比对，标出新增

**验收标准**：能一眼看出"今天新出现的事件"与"昨天已提过、今天有进展的事件"。

### 🟢 7. 多主题

**现状**：`briefs.topic_id` 字段存在，但永远是 `'default'`。
`Onboarding` 里选的"领域"（AI/芯片/具身/开发者工具）**没有影响任何东西**——选了白选。

**验收标准**：两个主题能各自配置源集合、各自排程、各自出简报。

**备注**：如果决定不做多主题，就把 Onboarding 那一步去掉——
留着一个不起作用的选择比没有更糟。

### 🟢 8. 搜索增强

**现状**：全文检索能用了，但只有单一输入框。

**缺口**：
- 没有按板块 / 来源 / 时间筛选
- 没有高亮命中片段
- 结果只按分数排序，不支持按时间排序

**验收标准**：能筛"只看研究板块、最近 7 天"，关键词在结果里高亮。

### 🟢 9. 导出格式

**现状**：只导出 markdown 到 `文档/Meerkat/`。

**缺口**：PDF、带样式的 HTML、复制为富文本。

**验收标准**：导出的 PDF 打开后中文不糊、链接可点。

### 🟢 10. 快捷键帮助

**现状**：`j/k/s/o/m/h`、`g/G`、`Ctrl+K` 都有，但界面上只有底部一行小字提示。

**验收标准**：按 `?` 弹出快捷键面板。

## 四、工程债

### 🟢 11. IPC 层没有测试

**现状**：204 个测试全在 `core/` 与 `app/` 的纯逻辑上。
`ipcMain.handle` 的 zod 校验、preload 与 `ipc-types.ts` 的契约**只有人肉验证**。

**风险**：preload 暴露的形状与类型声明不一致时，编译能过、运行时是 `undefined`。

**验收标准**：能对一组 handler 做"传入非法参数必须返回 `{ok:false}`"的测试。

### 🟢 12. 渲染层没有组件测试

**现状**：键盘导航、收藏切换、搜索防抖都只靠截图验证。

**验收标准**：至少覆盖 `BriefView` 的键盘模型（j/k 边界、s 切换、h 隐藏/撤销）。

### 🟢 13. 日志策略

**现状**：单文件超过 2MB 轮转，只留两代。

**缺口**：没有按天归档，排查"上周三那次失败"时可能已经被覆盖。

**验收标准**：按天分文件，保留 7 天。

### 🟢 14. 定时验收脚本被删了

**现状**：我为了清理，把 `scripts/prep-schedule.ts` 删了。以后要重跑"到点自动触发"的
真机验收，需要它来把排程设到 2 分钟后。

**验收标准**：脚本回到 `scripts/`，README 里写一句怎么用。

### 🟢 15. electron-builder 的重复依赖提示

构建日志里有一条：`@electron/rebuild already used by electron-builder,
please consider to remove excess dependency from devDependencies`。

**验收标准**：`pnpm rebuild:native` 改用 `electron-builder install-app-deps` 或直接删掉该依赖，
构建日志无警告。
